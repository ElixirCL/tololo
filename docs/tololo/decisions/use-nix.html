Use Nix with Devenv for dev environments

  • Status: accepted

  • Date: 2025-01-07

Context and Problem Statement

We want to declaratively define system dependencies (such as Elixir) and services (such as Postgres) to improve developer experience by streamlining setup and ensuring consistency.

Considered Options

  • Nix with Devenv: Tool based on the Nix package manager that allows declaratively defining system dependencies and services.

  • Nix Flakes: Lower level abstraction over Nix that allows creating dev shells with the system dependencies necessary to run the project. It lacks higher-level abstractions for managing services like Postgres.

  • Docker: Tool that allows running development containers locally. Heavier in resource usage.

  • Github Codespaces: Cloud hosted dev environment that runs an instance of Visual Studio Code in a browser. Relies on Github’s cloud services. Devenv can generate a devcontainer.json that’s compatible with it.

Examples

  • Nix + Phoenix.

  • Nix Phoenix Template.

Questions

Can we use Dev Containers?

A devcontainer.json file can be used as well?. Maybe we can support both Nix and Docker Dev Container, so Windows devs can have a dev environment too without WSL.

Answer

Devenv has a devcontainer integration which generates a devcontainer.json file using the same configuration as devenv.nix.

Decision Outcome

Chosen option: “Nix with Devenv”, because

  • Declarative and reproducible dev environments.

  • Devenv allows managing services such as Postgres in a per-project basis.

  • More lightweight than containers.

  • Doesn’t depend on external services such as Github.

Consequences

All system dependencies will be handled in the devenv.nix file at the root of the project. Contributors will need to install Nix and Devenv, but this upfront effort will reduce issues with setting up the environment in the future and ensure reproducibility.

This approach may complicate setup on systems using native Windows without WSL, due to Nix lacking support for it.
